# foodcore — the shared food-reference engine (unit conversion, USDA portion
# weights, deterministic nutrition, allergen + dietary screening). It lives in
# its own repository and is PINNED TO A COMMIT, deliberately.
#
# It used to be a directory in this repo installed by path, which made the
# dependency one-sided: an edit here took effect immediately, while Edibl — the
# other consumer — only saw it when someone remembered to bump a SHA. One app
# silently ahead of the other is the drift the cross-app rule exists to prevent.
# A pin on BOTH sides makes "shared code changes in all consumers together" a
# mechanism rather than a convention: upgrading becomes a visible, reviewable,
# bisectable commit in each repo.
#
# Pinned to a TAG rather than a raw SHA: "v0.2.0" tells a reader at a glance
# what two apps are sharing, where forty hex characters tell them nothing. The
# tag is immutable in practice because releases are cut, never moved.
#
# Bumping: move the tag here and in Edibl's requirements.txt in the same
# session, and check foodcore's own CI is green on that release first — it is
# the only signal either consumer has. v0.2.0 renamed the nutrient ids
# (energy -> calories, carbohydrate -> carbs, fat_total -> fat,
# fat_saturated -> saturated_fat, sugars -> sugar); anything mapping the old
# names must be deleted rather than re-pointed.
#
# Imported lazily, so the backend still runs (on its built-in densities) if the
# package is somehow absent.
foodcore @ git+https://github.com/Amantux/foodcore.git@v0.2.4
